# AGENTS.md - Coding Guidelines for FuncWork

## Overview

FuncWork is a TypeScript library for dynamically running pure functions inside Web Workers. Functions are serialized via `Function.prototype.toString()` and re-created inside a blob-based Worker.

## Toolchain

- **Build**: Vite 8 (Rolldown-powered), two-step: worker pre-build (`vite.worker.config.ts`) → library build (`vite.config.ts`)
- **Test**: Vitest 4 with happy-dom
- **Lint**: ESLint 9 flat config (`eslint.config.js`, `@antfu/eslint-config`)
- **Types**: TypeScript 5, strict mode, declarations generated by `vite-plugin-dts`
- **Docs**: VitePress site in `docs/` (deployed to GitHub Pages via `.github/workflows/deploy-docs.yml`)

## Commands

```bash
pnpm install        # install dependencies
pnpm test           # run tests once
pnpm test:watch     # watch mode
pnpm test:coverage  # coverage report
pnpm lint           # eslint check
pnpm lint:fix       # eslint autofix
pnpm typecheck      # tsc --noEmit (app + test configs)
pnpm build          # build dist/ (worker IIFE → ESM/CJS/IIFE + .d.ts)
pnpm docs:dev       # docs dev server
pnpm docs:build     # build docs site (pre-builds worker automatically)
```

## Architecture

- `src/index.ts` — `FuncWork` class: main-thread API (`add`, `invoke`, `remove`, `clear`, `list`, `destroy`). Uses `#private` fields and a pending-invocation map keyed by request id.
- `src/worker.ts` — Worker-side handler. Exports `handleMessage` (used by tests) and self-registers on `globalThis.onmessage`. Uses `eval` by design to re-create serialized functions.
- `src/utils.ts` — tiny helpers (`isFunction`, `uuid`).
- The worker script is bundled to an IIFE string at build time and injected as the `__WORKER_SCRIPT__` define; tests get it via `define` in `vitest.config.ts`.

## Code Style

- TypeScript strict mode; prefer `unknown` over `any`; use `(...args: any[]) => any` aliases only where user-supplied functions must be accepted.
- Use `#private` class fields for true privacy.
- Single quotes, 2-space indent, semicolons, trailing commas (enforced by ESLint — run `pnpm lint:fix`).
- No comments unless necessary; JSDoc allowed in public API.
- Early returns / guard clauses; validate inputs and throw descriptive `Error`s; `console.warn` for recoverable issues.

## Gotchas

- **Never put a FuncWork instance inside Vue's `ref()`/`reactive()`** — Proxies break private-field access ("Cannot read from private field"). Docs demo keeps the instance in a plain variable.
- Worker messages are JSON strings; results carry `{ id, data }` where errors arrive as `{ error: message }`.
- Registered functions must be named and pure (no closures over outer scope).
- `pnpm docs:build` requires `dist/worker.iife.js`, which its script builds first.

## Git Workflow

- Conventional commit format preferred (`feat:`, `fix:`, `docs:`…).
- CI runs lint, typecheck, test, and build on every push/PR (`.github/workflows/ci.yml`).
